# DELIS — обязательные действия владельца перед production

Кодовая часть release-hardening выполнена и покрыта автоматическими тестами.
Пункты ниже нельзя безопасно угадать, получить из кода или выполнить без
владельца кабинетов и физических устройств. Запуск live-платежей до закрытия
всех пунктов запрещён.

## 1. Юридические и бизнес-данные

- [ ] Подтвердить правильную форму продавца: **MChJ или YTT**. Сейчас интерфейс
  показывает `"DELIS GROUP" MChJ`, а старый комментарий о реквизитах ссылался
  на свидетельство YTT.
- [ ] Подтвердить наименование, ИНН/ЖШШИР, регистрационный номер, MFO, расчётный
  счёт, банк, юридический адрес и ФИО руководителя.
- [ ] Передать оферту, privacy policy, доставку, гарантию и возврат юристу.
- [ ] Утвердить русский и английский варианты юридических документов либо
  официально оставить документы только на узбекском с явным указанием языка.
- [ ] Подтвердить `hello@delis.uz`, Telegram менеджера и оба телефона.
- [ ] Добавить только существующие Instagram/YouTube страницы.
- [ ] Проверить реальные цены, остатки, фото, описания и характеристики 8 товаров.
- [ ] Заполнить себестоимость каждого активного товара, среднюю доставку и
  комиссию эквайринга в **Админка → Лояльность → Награды**. Требование:
  `Cost coverage = 100%`.
- [ ] Просмотреть все промокоды в админке и включить только утверждённые.
  Новая production-база создаёт демонстрационные коды выключенными.

## 2. Секреты production

Сгенерировать `BROWSER_SESSION_SECRET` командой:

```bash
openssl rand -hex 32
```

Заполнить в Render/VPS, не отправляя значения в чат или Git:

- [ ] `TG_BOT_TOKEN`
- [ ] `BROWSER_SESSION_SECRET`
- [ ] `TG_INIT_DATA_MAX_AGE_SECONDS=86400`
- [ ] `ADMIN_CHAT_ID`
- [ ] `APP_URL` — точный HTTPS origin без `/` в конце
- [ ] `PUBLIC_API_URL` — origin API без `/` в конце
- [ ] `BOT_USERNAME`
- [ ] `SUPABASE_URL`
- [ ] `SUPABASE_SERVICE_KEY` (`service_role`, только backend)
- [ ] `COURIER_CHAT_IDS`, если есть отдельные курьеры
- [ ] Убедиться, что `DELIS_DEV_ADMIN_TOKEN` отсутствует в production
- [ ] Оставить `ENABLE_SEEDED_PROMOS=false`

После настройки открыть Mini App администратором и проверить:

```text
GET /v1/admin/readiness
```

Поле `ready` должно быть `true`; каждый `fail` должен быть устранён.

## 4. Payme, Click и Telegram Stars

Сначала использовать только sandbox/test credentials.

- [ ] Payme Merchant ID и Key добавлены.
- [ ] Payme Merchant API URL: `https://<API>/v1/webhooks/payme`.
- [ ] Click Service ID, Merchant ID и Secret добавлены.
- [ ] Click PREPARE/COMPLETE URL: `https://<API>/v1/webhooks/click`.
- [ ] Админка → Платежи → «Проверить всё» не содержит `fail`.
- [ ] Payme: создать заказ, оплатить, повторить webhook и проверить отсутствие
  двойного cashback.
- [ ] Click: пройти PREPARE → COMPLETE, повторить COMPLETE и проверить
  идемпотентность.
- [ ] Telegram Stars: создать invoice через production-бота и оплатить.
- [ ] Проверить отмену, неверную сумму и неуспешный платёж.
- [ ] Только после sandbox-подтверждения заменить реквизиты на live.
